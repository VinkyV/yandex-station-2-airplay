# 10. Проверка «всё ли живо» одной командой

Скрипт `scripts/mac/verify-station.sh` отвечает на вопрос «колонка в порядке?» без захода
в SSH и без чтения логов. Ничего не меняет — только смотрит, и возвращает код 1, если
что-то не так (удобно для крона и для «после ребута проверь»).

```sh
STATION=<IP> KEY=~/.ssh/station sh scripts/mac/verify-station.sh
```

## Что проверяется

| Пункт | Почему это важно |
|---|---|
| SSH по ключу | основной канал доступа; без него остальное не проверить |
| метка `/data/quasar/activate_network_adb` | без неё после ребута SSH не поднимется |
| набор утилит (`jq`) | распакован ли musl-набор в `/data/local/opt/tools` |
| ровно один `nqptp` | два экземпляра дерутся за 319/320 и ломают синхронизацию AirPlay 2 |
| порт `7000` | приёмник слушает RTSP |
| процесс `shairport-sync` | приёмник вообще запущен |
| `avahi` | без него колонки не видно в сети |
| ровно один `maind --mediad` | две копии дерутся за звук, Алиса молчит |
| кадры в `/data/local/led` | иначе подсветка не включится |
| одна копия слушателя голоса | несколько копий дают двойные срабатывания фраз |
| `updatesd` отсутствует в `launch.json` | первый слой заморозки обновлений |
| `device_ota_update.sh` — заглушка | второй слой: сам применитель OTA |
| плеер `zvukd` | установлен ли свой плеер (не критично) |
| свободное место на `/data` | меньше 20 МБ — и установка/кэш начнут падать |
| ответ панели `/api/status` | сервер на `socat` жив, а не просто «порт занят» |

## Две ловушки, из-за которых наивная проверка врёт

1. **`readlink /proc/<pid>/exe` не работает для наших бинарников.** Приёмник, `nqptp` и `avahi`
   запускаются через musl-загрузчик, поэтому `exe` указывает на `ld-musl-aarch64.so.1`,
   а не на саму программу. Считать надо по `/proc/<pid>/cmdline` с полным путём.
2. **Проверка, отправленная одной длинной ssh-командой, считает себя.** Текст команды содержит
   имена процессов, и подсчёт по `cmdline` находит собственную оболочку — отсюда ложное
   «mediad: 2 копии». Правильно: отдать проверку на устройство отдельным файлом и пропускать
   свой pid и родителя.

Третья, косметическая: панель на `socat` занята обработкой соседнего запроса, поэтому запрос
к `/api/status` стоит повторять 2–3 раза, а не падать с первого раза.
