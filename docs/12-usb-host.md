# 12. USB-host (OTG) на Станции 2 (`yandexmidi`)

Порт Type-C у Станции 2 — как и у Станции Лайт — по умолчанию отдан **gadget-контроллеру**
(`dwc_otg`), то есть работает только как «устройство» (ADB, режим питания). Но железо умеет
и хост: тот же USB2-PHY, тот же контроллер `xhci`, просто порт не коммутирован.

Мы проверили это на своём устройстве (`YNDX-00051`, платформа `yandexmidi`, ядро `4.9.68`),
опираясь на рецепт для Станции Лайт: **[hackalice.me/recipes/usb-host](https://hackalice.me/recipes/usb-host/)**
(репозиторий [Marker284/yandex-station-extended](https://github.com/Marker284/yandex-station-extended),
каталоги `contrib/otg` и `contrib/modules`). Автор рецепта — он, наша часть — проверка на Midi,
скрипты автозапуска и грабли ниже.

## Что совпадает с Лайт, а что нет

| | Станция Лайт (`yandex,station-micro`) | Наша Станция 2 (`yandex,station-midi`) |
|---|---|---|
| SoC | `amlogic, axg` | `amlogic, axg` |
| Ядро | 4.9.68 | 4.9.68 |
| USB2-PHY | `ffe09000`, регистры `usb_r0/r1/r4`, `u2p_r0` | те же |
| `usb_r0` до переключения | `0x8000006A` | `0x8000006A` |
| `usb_r1` до переключения | `0x01002000` | `0x01000000` (бит уже снят) |
| `u2p_r0` | `0x10252000` | `0x10252000` |
| Симптом | `xHCI host not responding … HC died` в dmesg | точь-в-точь тот же |

То есть установщик из чужого репозитория на Midi просто откажется работать: у него жёсткая
проверка `yandex,station-micro`. Скрипты ниже — та же последовательность, но без этой проверки
и с нашими дополнениями.

## Что проверено на живом устройстве (24.10.2026)

Хаб с питанием (Genesys `05e3:0610`) + второй хаб (WCH `1a86:8091`), в нём:

* флешка — `/dev/sdb`, 8,18 ГБ, FAT32-раздел смонтировался только для чтения;
* SD-карта в картридере `05e3:0751` — `/dev/sda`, 7,4 ГБ (карта Sony, AVCHD);
* USB-Ethernet Realtek RTL8153 (`0bda:8153`) — после `r8152` появился интерфейс `eth0`;
* `usb-storage` и `uas` подхватили накопители, ядро не ругнулось ни разу.

Модули взяты из `contrib/modules` автора рецепта, контрольные суммы сошлись, vermagic подошёл:
`sd_mod`, `usb-storage`, `uas`, `mii`, `usbnet`, `r8152`. Аудиомодули (`snd-usb-audio`) мы
**не ставили** — не проверяли и не хотим, чтобы звук ушёл с динамика.

## Установка

```sh
# 1. на колонку: модули и скрипты
ssh -p 2222 root@<ip> 'mkdir -p /data/otg/modules'
cat sd_mod.ko usb-storage.ko uas.ko mii.ko usbnet.ko r8152.ko ... # положить в /data/otg/modules
cat otg-host.sh | ssh -p 2222 root@<ip> 'cat > /data/otg/otg-host.sh && chmod 755 /data/otg/otg-host.sh'
cat otg-off.sh  | ssh -p 2222 root@<ip> 'cat > /data/otg/otg-off.sh  && chmod 755 /data/otg/otg-off.sh'

# 2. автозапуск
mount -o remount,rw /
cat S97otg-host | ssh -p 2222 root@<ip> 'cat > /etc/init.d/S97otg-host && chmod 755 /etc/init.d/S97otg-host'
mount -o remount,ro /

# 3. перезагрузка; через ~10 с после старта смотреть
ssh -p 2222 root@<ip> 'cat /data/otg/last.log; ls /sys/bus/usb/devices/'
```

`scp` на прошивке нет (нет sftp-server) — файлы передаются через `cat файл | ssh 'cat > путь'`.

## Управление

```sh
/data/otg/otg-host.sh     # включить вручную (идемпотентно: если уже хост — только модули и скан)
/data/otg/otg-off.sh      # вернуть режим устройства без перезагрузки
touch /data/otg/disable   # выключить навсегда (автозапуск будет пропускать)
cat /data/otg/last.log    # что сделал скрипт
```

**Накопители.** FAT32 монтируется ядром (`CONFIG_VFAT_FS=y`):

```sh
mkdir -p /tmp/usb && mount -o ro /dev/sdb1 /tmp/usb   # только чтение — безопаснее
umount /tmp/usb
```

**Картридер требует пересканирования.** После вставки карты она не появляется: ридер не
сообщает о смене носителя. Помогает виртуальное переподключение устройства:

```sh
echo 1-1.2.1 > /sys/bus/usb/drivers/usb/unbind; sleep 2
echo 1-1.2.1 > /sys/bus/usb/drivers/usb/bind
```

Автозапуск делает пересчёт шины сам (6 проходов по 2 с), но только при старте.

**Сеть.** `eth0` появляется, как только загружен `r8152`; адрес выдаёт штатный `dhcpcd` при
подключённом кабеле.

## Грабли

| Симптом | Причина и что делать |
|---|---|
| Колонка зависла, ушла в перезагрузку | перед переключением пишется `/data/otg/boot-pending`; если он остался, следующая загрузка пройдёт **без** OTG. Убрать флаг вручную: `rm /data/otg/boot-pending` |
| `xHCI host not responding … HC died` при загрузке | это и есть исходное состояние: порт не коммутирован. После `otg-host.sh` ошибка исчезает |
| `can't create /sys/class/scsi_host/*/scan: nonexistent directory` | на раннем старте каталога ещё нет; в наших скриптах glob проверяется, ошибка безвредна |
| Карта не видна после вставки | см. `unbind`/`bind` выше |
| `mount: Invalid argument` на разделе | ext4/exFAT/NTFS ядро не умеет. **ext4 поставить нельзя**: модуль ходит в `current->journal_info`, а `task_struct` у Яндекса патченная — это гарантированный oops (проверено автором рецепта на `exfat`). Для exFAT/NTFS нужен FUSE-драйвер, у нас он не установлен |
| ADB по USB пропал | так и должно быть: порт занят хостом. SSH по Wi-Fi работает |

## Риски, честно

* Модули собраны не нами и не из исходников Яндекса (их нет в открытом доступе). У нас они
  загрузились без ошибок, но совпадение структур ядра — не гарантия: проверяйте `dmesg` после
  первого включения.
* Эксклюзивность: пока порт в режиме хоста, USB-gadget (ADB, режим прошивки через USB) недоступен
  до перезагрузки.
* Питание: Type-C на колонке — только вход. Нужен хаб с Power Delivery, иначе периферия не
  заработает (порт не отдаёт 5 В наружу).
