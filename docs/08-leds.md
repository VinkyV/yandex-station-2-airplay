# 08. Подсветка кольца

Бонус после root: кольцо станции можно заставить светиться как угодно — например, дышать
триколором, пока играет AirPlay. Никакого облака и никаких директив: всё через framebuffer.

## Как устроено кольцо

```
/dev/fb0          89 пикселей в одну строку, 32 бита на пиксель → 356 байт на кадр
байты пикселя     R, G, B, X   (четвёртый байт не используется)
```

Проверяется без всякой документации:

```sh
cat /sys/class/graphics/fb0/virtual_size   # 89,1
cat /sys/class/graphics/fb0/stride         # 356
```

Штатные анимации лежат в `/system/vendor/quasar/ledpatterns/panel/*.led` и имеют ровно тот же
размер кадра: `alice_listening.led` = 189755 байт = 533 кадра по 356. То есть формат совпадает
с framebuffer'ом, только кадров много.

## Как узнать раскладку каналов (без гадания)

Снять кадры, пока Алиса говорит, и сравнить их между собой:

```sh
# на колонке: 900 кадров по 50 мс
(for i in $(seq 1 900); do dd if=/dev/fb0 bs=356 count=1 2>/dev/null >> /data/local/tmp/fbdump.bin; sleep 0.05; done) &
```

Потом на компьютере: найти самый частый кадр (обычно чёрный), вычесть его из остальных и
посмотреть, какие байты внутри пикселя меняются. У Midi меняются первые три (R, G, B), четвёртый
постоянный. Цвет «Алиса слушает» при этом R≈39, G≈3, B≈51 — фиолетовый.

## Проигрывание паттерна

`led-lamp.sh` (см. [`scripts/device/led-lamp.sh`](../scripts/device/led-lamp.sh)):

```sh
led-lamp.sh start tricolor      # дыхание триколором (белое → синее → красное)
led-lamp.sh start violet        # другие готовые: violet, warm, blue, green, red
led-lamp.sh solid solid_white   # ровный свет
led-lamp.sh stop                # погасить
```

Паттерн — файл `/data/local/led/<имя>.pat`: последовательность кадров по 356 байт. Скрипт листает
их через `dd if=pat of=/dev/fb0 bs=356 skip=N count=1 conv=notrunc` и спит 70 мс между кадрами.

Паттерны генерируются на компьютере: [`scripts/build/led-patterns.py`](../scripts/build/led-patterns.py).

## Подключение к AirPlay

В `audio-owner.sh` (распорядителе звука):

* началась сессия → `led-lamp.sh start tricolor`;
* сессия кончилась → `led-lamp.sh stop`;
* пока играет — проверка, что подсветка жива, иначе запустить заново.

## Грабли, на которые наступили

| Симптом | Причина | Лечение |
|---|---|---|
| Свет не появляется вовсе | писали в `/dev/fb0`, но кадр собирался через `awk printf "%c"` | busybox-awk не имеет `cos()`, а `printf "%c"` для байтов >127 пишет UTF-8 (2 байта) — кадр «съезжает». Кадры готовить заранее (python) и заливать как файлы |
| Писали цвет — получили белый/розовый | тот же сдвиг байтов | то же |
| Кольцо застыло на последнем цвете | цикл убит посреди кадра, «гашение» перезаписал уже следующий кадр | `stop` ставит флаг, ждёт выхода цикла (0.4 с), потом пишет нули |
| Подсветка не гаснет после остановки | признак «играет» определялся по TCP | AirPlay 2 держит служебное соединение и после остановки — определять по тому, что приёмник **держит ALSA-устройство** (`/proc/<pid>/fd` → `pcmC0D0p`) |
| Скрипт убивает сам себя по SSH | `grep`/`awk` по шаблону совпадает с командной строкой вызывающего | искать процессы через `/proc/*/cmdline`, исключая `$$` и `$PPID` |

## Что можно дальше

* **Цветомузыка.** Настоящая требует доступа к семплам: сейчас приёмник отдаёт звук прямо в ALSA,
  точку съёма надо организовывать отдельно (петля или pipe-выход у shairport-sync).
  Пока сделано «дыхание», привязанное к состоянию, а не к громкости.
* **Разные цвета под разные состояния** (пауза, ошибка, загрузка).
* **Ночной режим** — приглушать до 10–15% яркости по расписанию.
