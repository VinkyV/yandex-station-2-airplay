# 01. Получение root на Midi

Что нужно: компьютер с `uv`, `make`, `adb` и Python (ставит `uv`), роутер с возможностью
прописать статические DNS-записи, полный доступ к самой колонке.

Обозначения: `<STATION_IP>` — адрес колонки, `<PC_IP>` — адрес компьютера в той же сети,
`<DEVICE_ID>` — Quasar `device_id` из приложения, `<PLATFORM>` — `yandexmidi` для Midi.

## Шаг 1. Инструменты автора

```sh
git clone https://github.com/hu553in/yandex-station-root
cd yandex-station-root
make setup                      # uv sync --locked
cp config.example.mk config.mk
```

`config.mk`:

```make
STATION_IP := <STATION_IP>
STATION_DEVICE_ID := <DEVICE_ID>
STATION_PLATFORM := yandexmidi
PROXY_IP := <PC_IP>
```

Манифест прошивки в `firmware/update_manifest.json` менять не обязательно: если не собираетесь
подсовывать старую сборку, оставьте как есть — прокси по умолчанию отвечает «обновлений нет».

## Шаг 2. DNS на роутере

Три имени должны вести на компьютер — **только на время работы**. В Keenetic это делается
в командной строке (`http://<router>/` без `/dashboard`, либо telnet):

```
ip host quasar.yandex.net <PC_IP>
ip host quasar.yandex.ru <PC_IP>
ip host scbh.yandex.net <PC_IP>
system configuration save
```

Проверка: `dig +short A quasar.yandex.net @<router>` → `<PC_IP>`.

Побочный эффект: телефон с приложением «Дом с Алисой» тоже попадёт на компьютер, поэтому
на время активации телефон лучше держать на мобильном интернете.

## Шаг 3. Сброс колонки

Полный сброс (кнопка выключения микрофонов при подаче питания, отпустить на жёлтом свете):
прошивка откатывается к заводской, Wi-Fi и аккаунт стираются. Wi-Fi **не настраиваем**, пока
не поднят прокси.

На Midi после сброса часто «догорает» ранее скачанное обновление (образ лежит в `/bkupgrade`)
— колонка может 10–15 минут показывать обновление и не отвечать.

**Что делали мы: не ждали.** Питание выдёргивалось вилкой, колонка включалась обратно, и на
следующей загрузке снова шла за конфигом — окно открывалось именно там. Обновление при этом
ни разу не завершилось (см. ниже «Честная оговорка»).

Ждать или обрывать — решаете вы: ожидание безопаснее, обрыв быстрее и повторяемее. Колонка
обрывы питания переживала спокойно (поднималась с синим миганием, прошивка и `/data` целы),
но это не гарантия, а везение.

## Шаг 4. Прокси

```sh
make offer                    # необязательно: зарядить старую сборку
sudo make proxy OFFER_UPDATE=1
```

Важно: логи mitmproxy **буферизуются**, если направить их в файл. Надёжнее следить за файлами
состояния:

* `private/enable_state.json` — появился/обновился → конфиг подменён, отладка включена;
* `private/offer_receipt.json` — фаза `armed` → `spent` → колонка забрала манифест.

Если очень нужен живой лог:

```sh
sudo env PYTHONUNBUFFERED=1 make proxy OFFER_UPDATE=1 2>&1 | tee private/proxy.log
```

## Шаг 5. Активация

Включаем колонку, в приложении настраиваем Wi-Fi. Колонка приходит за конфигом, прокси
подменяет ответ и включает `adbd` — в этот момент появляется `private/enable_state.json`.

Дальше колонка может уйти в обновление (своё, из `/bkupgrade`). Ждём загрузки.

## Шаг 6. Окно отладки

ADB открывается на **десятки секунд** после загрузки/применения конфига. Самый предсказуемый
способ поймать окно — **перезагрузить колонку питанием** (выдернуть вилку и включить) при уже
поднятом прокси: окно повторяется на каждой загрузке, пока целы метки в `/data/quasar`.

Ловить поллером:

```sh
while :; do
  nc -z -w1 <STATION_IP> 5555 && { adb connect <STATION_IP>:5555; break; }
  sleep 2
done
adb shell id     # uid=0(root)
```

На Midi сетевой `adbd` живёт недолго: облачный конфиг снимает метки активации и гасит его.
Поэтому всё нужное надо успеть сделать в окно — или сразу ставить SSH (см. `02-persistence.md`).

## Что делать, если окно не появилось

- Проверить, что DNS всё ещё указывает на компьютер и адрес колонки не изменился после сброса
  (MAC у Midi может смениться, смотреть в списке клиентов роутера; OUI `B8:87:6E` — Yandex).
- **Дёрнуть питание** (выдернуть вилку, включить): окно повторяется на каждой загрузке, пока
  целы метки в `/data/quasar`. Это надёжнее, чем ждать очередного «догорания» обновления.
- Проверить, что прокси действительно получил запрос: `private/enable_state.json` обновился
  по времени.
- Если метки уже сняты облаком — нужен новый цикл: сброс → конфиг → окно.

## Честная оговорка про обновление

**Ни одного завершённого обновления мы не видели**: питание выключалось вручную примерно через
10–15 минут после его начала, а иногда заметно раньше. Отсюда два следствия:

* «прошивка до и после сброса — одна и та же `.50`» — это факт;
* «сброс перепрошивает колонку заранее скачанным образом» — **не доказано**: различить
  «обновление не успело примениться» и «применилось, но на ту же сборку» нашими данными нельзя.

Практический вывод: если дать обновлению доиграть и колонка штатно перезагрузится, окно
активации закрывается — и подмена конфига перестаёт работать. Поэтому в методике полезно
фиксировать три вещи: **был ли сброс**, **прерывалось ли обновление и на какой минуте**,
**какая сборка была до и после**.

## Про `.50`

В README метода сказано, что сборка `.50` отвергает сертификат. На `yandexmidi` (проверено на
`0.369.1.50.*`) подмена проходит. На `yandexmini_2` того же поколения — нет. Вывод: **проверять
на своём устройстве**, а не судить по номеру сборки.
